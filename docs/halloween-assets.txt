UMAMI holiday decorations (2026-10-19)

Switch: Admin > Holiday decorations (/admin/holiday-decorations) > Halloween.
It saves immediately, subject to
site_settings.update permission. Refresh an already-open public page to see the
change. The default is OFF when the setting is absent. Local preview is enabled.
No dates, automatic enabling, or external scripts are added.
The setting is stored as halloween_enabled in site_settings and uses the existing
setting audit observer. No schema migration is needed.
The page requires site_settings.view; changes require site_settings.update.
Add implemented holidays to App\Support\HolidayDecorations::CATALOG with their
setting key, handler (enabled/setEnabled), preview and localized name. Public
rendering/assets must also be implemented before adding a holiday to the catalog.
Only registered holidays can be changed. No raw keys are editable in the admin.

Scope: homepage and public menu pages, all three languages. Checkout, tracking,
legal pages and the admin panel do not display decoration. Off means no decorative
markup, stylesheet, script or image requests. Motion pauses in a hidden tab and
when the basket or product dialog is open. Reduced-motion users see static corner
webs and pumpkins only. All decorative elements are noninteractive and hidden from
screen readers. The original design, copy and ordering logic are unchanged.

Artwork: generated with the built-in image_gen tool, transparent PNG originals.
Project assets are resized WebP copies with preserved alpha, in:
public/assets/umami/halloween/{pumpkins,web,bat,leaf}.webp
The side-profile sprite is bat-profile.webp (8170 bytes). Combined image size:
171142 bytes. Original generated PNGs remain in Codex's
generated_images directory. No third-party image hotlinks or runtime dependency.

Animation update: frontal bats hover at the viewport edges; side-profile bats fly
in both directions with randomized heights, speed and intervals. Desktop starts
a flight every 1.1-2 seconds (maximum 6 concurrent), mobile every 1.6-2.5 seconds
(maximum 3 concurrent). Finished nodes are removed. Scrolling does not stop flight
generation. Hidden tabs, basket and product dialogs pause both scheduling and
active flights. Reduced-motion changes remove/resume flights without a reload.
